# FRL-02K-C2A: Production Triggered TARGET Provider Seam for Blood Operative

## Status

Approved design baseline for implementation planning. This document records the
architecture and test contract approved after the C2/C2R audit and C2A design
review. It is intentionally narrower than a general triggered-target
framework: only the exact Blood Operative ETB TARGET profile is admitted.

## 1. Objective and boundary

C2A introduces a production seam for the stack-time TARGET decision of the
admitted Blood Operative enter-the-battlefield trigger. A controller-local
external resolver may own Target A when configured; when it is absent, the
native Forge path remains the owner.

The seam must prove ownership transfer, preserve the existing
`DECISION_TRACE_V2` provenance contract, fail closed for unsupported targeted
triggers under external ownership, and preserve Forge stack/fizzle behavior.

The following remain outside C2A:

- Blood confirmation Target B ownership;
- generic triggered TARGET admission beyond the exact Blood profile;
- generic CONFIRMATION, PAYMENT, ORDER, or DAMAGE_ASSIGNMENT seams;
- observation/history or hidden-information redesign;
- edits to card scripts, Lazav behavior, or native stack mechanics.

## 2. Ownership architecture

```text
PlayerController
  owns one controller-local TargetDecisionProvider
  owns one nullable controller-local TargetDecisionProvider.Resolver

PlayerControllerAi
  thin routing only

TriggeredTargetDecisionCoordinator
  stateless profile admission, classification, orchestration,
  native teacher mapping, trace provenance, and fail-closed integrity

TargetDecisionProvider
  generic Forge legality, candidates, forced status, request creation,
  and TargetChoices application only
```

The coordinator must not be Blood-named. The generic provider must not know
Blood semantics, profile admission, teacher mapping, ownership policy, or
resolver behavior.

The resolver contract may be defined in the generic decision namespace as a
functional `Resolver` receiving a `DecisionRequest` and returning a
`LegalCandidate`. The provider itself need not retain the resolver. No
provider, coordinator, resolver, or request-id state is static.

## 3. Applicability and ownership classification

The coordinator classifies a wrapped triggered ability as:

```text
NOT_APPLICABLE
ADMITTED
UNSUPPORTED_TARGETED_TRIGGER
```

`NOT_APPLICABLE` is narrow: no trigger, or no player-owned TARGET decision.
Ordinary non-targeted triggers remain native.

An agent-required/player-owned targeted trigger with the exact Blood profile is
`ADMITTED`. Every other agent-required/player-owned targeted trigger is
`UNSUPPORTED_TARGETED_TRIGGER`, including copied, generated, non-intrinsic,
non-normal, static, `SpawningAbility`, `TargetingPlayer`, and unknown targeted
profiles.

```text
resolver == null
  NOT_APPLICABLE                  -> existing native Forge path
  ADMITTED                        -> native Forge path with teacher capture
  UNSUPPORTED_TARGETED_TRIGGER    -> existing native Forge path

resolver != null
  NOT_APPLICABLE                  -> existing native Forge path
  ADMITTED                        -> external Target A ownership
  UNSUPPORTED_TARGETED_TRIGGER    -> integrity failure; no Forge-AI fallback
```

Thus the hard fail for unsupported targeted profiles is scoped to active
external ownership. The separate ambient-continuation invariant for an
admitted Blood preparation applies regardless of resolver state.

## 4. Exact admitted profile

The profile identifier is:

```text
BLOOD_OPERATIVE_ETB_EXILE_GRAVEYARD_CARD_TARGET
```

Admission requires independent source/provenance, static-trigger, and live
ability validation. A static hit alone is insufficient.

### 4.1 Source and provenance

The source must be Blood Operative and public to the chooser/decider. It must
be in the Original card state and not cloned. The triggered wrapper must also
not be copied; copied-trigger provenance is a separate rejection from
cloned-source provenance. The trigger must be intrinsic, normal, non-static,
and not generated by a `SpawningAbility`.

### 4.2 Static trigger semantics

The normalized semantic projection must be:

```text
Mode            = ChangesZone
Origin          = Any
Destination     = Battlefield
ValidCard       = Card.Self
OptionalDecider = You
Execute         = TrigChangeZone
```

`TriggerDescription` and `TgtPrompt`/localized prompt text are descriptive and
are not admission evidence. Unknown semantic parameters reject the profile.
Comparison uses normalized semantic projections with explicit allow/deny
checks, not raw parameter-map equality, so known nonsemantic runtime
decoration does not cause a false reject.

### 4.3 Live underlying ability semantics

Admission must inspect the exact live `wrapper.getWrappedAbility()` object. The
underlying effect must be:

```text
API              = ChangeZone
Origin           = Graveyard
Destination      = Exile
Valid targets    = Card
target zone      = Graveyard
MinTargets       = 1
MaxTargets       = 1
random targeting = false
TargetingPlayer  = absent
```

There must be no additional target group, subability, target list, cost,
payment, or semantic effect changing this single card-target operation. The
underlying effect must not have `Optional$ True`: Blood optionality is only
trigger-level `OptionalDecider=You`.

The underlying target list must be empty before C2A preparation:

```text
underlying.getTargets().isEmpty() == true
```

Otherwise admission fails with `NON_EMPTY_INITIAL_TARGETS`.

### 4.4 Chooser identity

The exact chooser must be the same Forge player/seat for:

```text
wrapper.decider
underlying.activatingPlayer
source.controller
```

This means the same Forge player entity/seat, not arbitrary JVM object
identity. A `TargetingPlayer` override or chooser mismatch is unsupported.

## 5. Stateless coordinator and preparation handle

`TriggeredTargetDecisionCoordinator` has no request-local fields. Native teacher
capture uses a request-local preparation/result object containing, as needed:

- the exact live underlying `SpellAbility` reference;
- the generated `DecisionRequest`, when one exists;
- an immutable before-callback target snapshot;
- the request-local trace handle or completion data;
- classification and preparation status.

The snapshot is not a live `TargetChoices` object. It preserves the target
identities and count required to identify exactly one new target after the
native callback without re-enumerating the provider.

Before generating a request for admitted Blood, require:

```text
PriorityActionDiagnostics.hasActiveActionContinuation() == false
```

If active, throw `UNSUPPORTED_ACTION_CONTINUATION` before provider generation,
resolver invocation, or `brains.doTrigger`, even when `resolver == null`.
When clear, call the provider with `continuation = null` and require:

```text
hasActionContinuation = false
decisionSequenceId     = null
subdecisionIndex       = null
```

## 6. Native compatibility path

With `resolver == null`, existing Forge ownership is preserved for all trigger
classes. For an exact Blood trigger, one neutral provider pre-enumeration may
create a teacher capture:

```text
provider.generateTargetRequest(underlying, chooser, null)
```

If it returns `INVALID_TARGETING`, there is no request or teacher capture.
`brains.doTrigger(underlying, mandatory)` still runs exactly once with its
normal false/no-stack behavior.

If it returns a `DecisionRequest`, store its immutable snapshot, then invoke
`brains.doTrigger` exactly once. Forge AI remains the decision owner. Mapping
uses the existing snapshot; it performs no second provider generation and no
second AI call.

Other targeted profiles and non-targeted triggers use the existing native path
unchanged when no resolver is configured.

## 7. External ownership path

With `resolver != null`, `NOT_APPLICABLE` remains native. An unsupported
targeted trigger throws a sanitized `TriggeredTargetIntegrityException`; it
must not call `brains.doTrigger`, invoke Forge AI, or push a stack item.

For admitted Blood, use `wrapper.getWrappedAbility()` and call:

```text
request = provider.generateTargetRequest(underlying, chooser, null)
```

The provider owns legality and application; the coordinator owns only the
following orchestration:

```text
INVALID_TARGETING
  -> no resolver, no mutation, normal no-stack result

request.isForced()
  -> resolver calls = 0
  -> provider.apply once
  -> returned status must be COMPLETE
  -> recordEngineForced()
  -> existing stack push

non-forced request with 2+ candidates
  -> resolver exactly once
  -> validate returned candidate
  -> provider.apply once
  -> returned status must be COMPLETE
  -> recordExternalChosenResult(candidate)
  -> existing stack push
```

`request.isForced()` is the authoritative forced branch. After apply, any
status other than `COMPLETE` is `TARGET_APPLICATION_INCOMPLETE` and prevents
the stack push.

`TargetDecisionProvider.apply()` may internally generate a completion request.
That provider-internal completion assessment is allowed; there may not be a
second externally visible policy request or teacher request.

## 8. Candidate and resolver integrity

An external resolver must return a non-null candidate belonging to the exact
request candidate set and still legal for the exact live ability. Null,
foreign, other-request, stale, and illegal candidates fail closed. The
coordinator must not substitute, retry, call Forge AI, or use a fallback.

External resolver/application failures must never call or emulate
`recordMappingFailed()`. If an external trace handle is already open, an
adversarial invalid run may later be `TRACE_INCOMPLETE`; no new V2 result kind
is required.

## 9. Native mapping contract

For a captured native decision:

```text
nativeResult == true
exactly one new target
new target maps uniquely to an existing request candidate
  -> recordNativeMappedResult(candidate)
```

`nativeResult == false`, zero/multiple new targets, foreign targets, missing
candidate mappings, and non-unique mappings are native mapping failures. The
coordinator calls `recordMappingFailed()` and then raises the controlled
integrity exception. This is the only C2A use of `MAPPING_FAILED`.

The separate native `INVALID_TARGETING` case has no request/capture and no
mapping attempt; Forge AI still runs once and normal no-stack behavior remains.

## 10. Trace contract

Use `DECISION_TRACE_V2` only:

| Path | Result | Native callback | Mapping | BC sample |
| --- | --- | --- | --- | --- |
| native strategic TARGET | `CHOSEN` | `true` | `true` | eligible |
| native forced TARGET | `FORCED` | `true` | `true` | excluded |
| external strategic TARGET | `CHOSEN` | `false` | `false` | excluded |
| external forced TARGET | `FORCED` | `false` | `false` | excluded |

Native uses `recordNativeMappedResult(candidate)`, external strategic uses
`recordExternalChosenResult(candidate)`, and external forced uses
`recordEngineForced()`.

Extend `DecisionTraceTrainingValidator.isHistoryValid()` narrowly so external
`CHOSEN` is valid for `DecisionType.CONFIRMATION` **or** `DecisionType.TARGET`,
while retaining the existing non-forced, candidate-membership, and false/false
native/mapping requirements. Do not free all decision types.

Leave `isBCPolicySample()` unchanged and strict: external and forced TARGETs
are not teacher samples.

Request IDs are monotonic only within each provider/controller. Controllers may
both issue `0, 1, 2, ...`; global uniqueness is neither required nor tested.

## 11. Hidden-information and exception boundary

Existing provider visibility checks remain authoritative. Traces and exception
messages must not contain hidden card names, raw target identities, or raw
resolver output. Runtime identity keys used for request-local candidate
membership are not semantic public data.

Introduce generic `TriggeredTargetIntegrityException` rather than reusing
`UnsupportedTargetDecisionException`, whose message exposes a host-card name.
Use sanitized reasons including:

```text
UNSUPPORTED_TARGETED_TRIGGER
UNSUPPORTED_PROFILE
LIVE_EFFECT_MISMATCH
NON_EMPTY_INITIAL_TARGETS
INVALID_EXTERNAL_CANDIDATE
TARGET_APPLICATION_INCOMPLETE
MAPPING_FAILED
UNSUPPORTED_ACTION_CONTINUATION
```

An integrity failure does not silently fall back or push a partially prepared
stack item.

## 12. Target A/B/C and stack boundary

C2A owns Target A at stack-time: the authoritative target on the live
underlying ability consumed by the ChangeZone effect. The external A path must
not call `brains.doTrigger`.

The existing native `confirmTrigger` may still temporarily evaluate Target B
later. This is an allowed integration/compatibility path, not C2A's second
TARGET decision and not fully externally owned Blood behavior. Target C remains
the effect-consumed target from the stack-resident ability.

After successful application and revalidation, the coordinator returns to the
existing Forge stack push. No retarget or new TARGET request is introduced
after push; ordinary fizzle behavior remains unchanged.

## 13. Test contract

Add a coordinator-oriented suite separate from generic provider tests.

### 13.1 Admission and classification

Cover exact Blood admission, static/live mismatch, runtime rewrite, copied
wrapper versus cloned source, generated/non-intrinsic/static/non-normal/
`SpawningAbility` triggers, `TargetingPlayer`, chooser mismatch, descriptive
text changes, unknown semantic parameters, unsupported targeted profiles, and
non-targeted native behavior. Verify resolver-null fallback versus resolver-on
hard fail.

### 13.2 External 0/1/many and adversarial resolver

Cover zero legal candidates, forced one candidate with zero resolver calls, and
two-plus candidates with one resolver call and one apply. Require `COMPLETE`
after every successful apply. Cover null, foreign, other-request, stale, and
illegal resolver candidates; every such case must fail closed and never be
`MAPPING_FAILED`.

### 13.3 Native teacher and ownership proof

Require exactly one pre-native request/snapshot generation, exactly one
`brains.doTrigger`, no second teacher generation, and immutable-snapshot
mapping. Cover valid mapping plus false, zero, multiple, foreign, and
non-unique mapping failures. The native invalid-targeting case has no capture
and still calls Forge once.

Use separate deterministic control and external runs. The native control
establishes `A_native` with one Forge-AI call. The external run invokes the
resolver once, invokes Forge AI for A zero times, and requires
`A_external != A_native` where practical. Never call Forge AI inside the
external path merely to discover its preference.

### 13.4 Continuation, trace, visibility, and isolation

An active ambient continuation on admitted Blood fails before provider,
resolver, or Forge-AI calls, even with resolver null. Verify null continuation
metadata, V2 native/external/forced provenance, external TARGET validator
acceptance without BC admission, external failures not masquerading as
`MAPPING_FAILED`, hidden-information safety, state/RNG neutrality,
stack/fizzle/no-retarget behavior, and controller/provider isolation.

### 13.5 Regression/workload locks

Retain the approved B1/C/C1/C2 locks:

```text
confirmTrigger = 26
Gelectrode admitted = 17
other no-cost = 5
cost-bearing = 1
untrusted = 3
confirmAction = 8
chooseBinary = 2
payCostToPreventEffect = 5
Blood = 2
Lazav = 3
```

Retain native A==C and native A/B divergence evidence. The canonical native
workload is Izzet Guild Kit versus Dimir Guild Kit, ten games, seed `20260810`.
External workload is Blood-focused only; do not claim full external Blood
behavior while confirmation remains native.

## 14. Scope status and handoff

```text
Blood Operative ETB TARGET: SUPPORTED (exact profile only)
global triggered TARGET:    OPEN
Blood CONFIRMATION:         OPEN
global CONFIRMATION:        OPEN
```

Implementation must preserve these boundaries, run focused then broad relevant
verification, record exact evidence, and avoid edits to unrelated decision
families or the Blood script. The final handoff must use the requested 47
sections, include a draft PR without merging, and end at the explicit STOP
boundary. The milestone verdict is `FRL_02K_C2A_PASS`, `PARTIAL`, or `FAIL`
according to the measured evidence; no success label is valid without tests,
build/checkstyle/diff evidence.
